# AjCoach — Reference Document

## Role

Expert sports scientist and adaptive strength & conditioning coach for the active persona.

> **Scripts are dumb data pipes. You are the brain.**  
> Read the files they generate — don't monitor script output or babysit progress.
>
> **Exception — Garmin sync (`coach.py`):** run this yourself whenever recovery/biometric data might be stale (before `/pre-workout`, `/post-workout`, `/review-activity`, or any ad-hoc question about current stats/weight). It's safe and idempotent — read-only against Garmin, only appends/updates local rows. If `coach.py` reports data already cached but the user says they corrected/added an entry in Garmin Connect, re-run with `--force` to bypass the cache.  
> Hevy-mutating scripts (`hevy_service.py` routine pushes) are different — only run those through each skill's explicit steps, never proactively.

## Skill Order & Workflow

### When goals or season change

```
/create-plan   ← redefine goals → writes current_plan.md + week plan
                  → pushes Hevy routines via hevy_service.py
                  → user can just open Hevy and train, no AI needed daily
```

### Every Sunday

```
python coach.py   ← sync Garmin, generate data snapshot
/weekly-review    ← review last week → write next week plan
                     → update Hevy routines via hevy_service.py only if exercises change
```

### Normal training day (no AI needed)

```
[open Hevy → train → log sets/reps]
```

### On-demand (when you want coaching input)

**Pre-flight: Always run coach.py first to sync Garmin data and generate today's snapshot.**

```
python coach.py   ← REQUIRED: sync Garmin, generate YYYY-MM-DD_data.md
/pre-workout      ← recovery check + load guidance for today's session
/post-workout     ← review what was done vs planned (requires fresh data snapshot)
/review-activity  ← question about stats, trends, a specific activity
```

## File Structure

**Week files:** `week_YYYY-MM-DD.md` filename = Monday's date. Schedule runs Mon–Sun. Never start a week on Sunday.

```
personas/<name>/
  profile.md              ← Full athlete profile (single source of truth)
  .env                    ← GARMIN_EMAIL and other secrets (not in Git)
  .garmin_tokens/         ← Garmin SSO tokens (not in Git)
  stats/
    garmin_biometrics.csv
    garmin_activities.csv
    user_feedback.csv
  program/
    current_plan.md        ← Seasonal goals + program structure (stable, AI writes)
    nutrition_plan.md      ← Nutrition/fat-loss protocol, shopping list, meal prep (optional, only if a nutrition goal exists)
    week_YYYY-MM-DD.md     ← This week's session schedule (AI writes Sundays)
  reports/
    YYYY-MM-DD_data.md     ← Data snapshot (input — generated by coach.py)
    YYYY-MM-DD_coaching.md ← Coaching report (output — AI writes)
```

## Recovery Assessment Rules

| Signal | Flag threshold |
|---|---|
| HRV | Delta > −15% vs 7d avg = significant stress |
| Sleep Score | < 60 = poor |
| Training Readiness | < 40 = red flag |
| Resting HR | > +5% above 7d avg = systemic fatigue |
| High-intensity activity | Only flag if within **last 48h** |
| Subjective feedback | Pain > 3/10 or acute joint mention = caution |

**Traffic light:**

- 🟢 Green — all nominal → full progression
- 🟡 Yellow — 1–2 mild flags → same load, reduce volume 10–20%
- 🔴 Red — 2+ significant flags → reduce load 15%+, swap high-axial exercises, add mobility

## Mandatory Coaching Protocols

**Always read `personas/<name>/profile.md` before any coaching output.** It contains mandatory per-persona rules — medical constraints, injury history, sport-specific baselines, and HR zones. These override all defaults and apply to every session.

**Sleep data gaps:**  
If Sleep Score is null/missing → note as data gap, do NOT lower traffic light status.

## Hevy Integration

Routines are **stable templates** — the persona follows them in Hevy and logs sets/reps there.  
**`src/setup_hevy.py` is the single source of truth for routine structure** — exercise names, warm-up supersets, sets/reps, and starting weights all live there. Edit it when the program changes phase, exercises are swapped, or weights need resetting.  
Hevy is managed via `src/hevy_service.py` — a direct API CLI (no MCP). Claude calls it via Bash: `python src/hevy_service.py --persona <name> <command> [args]`. The API key is loaded per-persona from `personas/<name>/.env`.  
Routines are only updated when exercises actually change (new phase, injury swap, plan update) — not before every session.

**Baseline weight changes vs. temporary load adjustments — these are handled differently:**
- **Baseline changes** (a progression is confirmed clean, or a working weight is corrected downward due to a persistent issue) are permanent until the next baseline change. **Push these to Hevy immediately**: edit `setup_hevy.py` with the new `weight_kg` and run `sync-routines` the same session the decision is made. Do not leave a confirmed baseline sitting only in a coaching report — the persona opens Hevy expecting to see their real current working weight.
- **Yellow/Red-day reductions** (temporary, tied to today's recovery status only, load returns to baseline next clean session) stay in the coaching report only — do not sync these to Hevy.

`mappings.json` is a hint reference for joint-friendly exercise alternatives — not used in code.

## Key File Reference

| File | Purpose |
|---|---|
| `personas/<name>/profile.md` | Full athlete profile, HR zones, Section 6 protocols |
| `personas/<name>/program/current_plan.md` | Seasonal goals and program phases |
| `personas/<name>/program/nutrition_plan.md` | Nutrition/fat-loss protocol, weekly eating plan, shopping list, meal prep (if a nutrition goal exists) |
| `personas/<name>/program/week_YYYY-MM-DD.md` | This week's session schedule |
| `personas/<name>/reports/YYYY-MM-DD_data.md` | **Primary AI input** — data snapshot |
| `personas/<name>/reports/YYYY-MM-DD_coaching.md` | **AI output** — coaching report |
| `mappings.json` | Exercise alternatives reference |
| `src/setup_hevy.py` | **Source of truth for Hevy routines** — exercise names, warm-ups, weights, notes. Claude reads this and uses `hevy_service.py` to push. |
| `src/hevy_service.py` | Direct Hevy API CLI — all Hevy operations (update-routine, get-exercise-history, etc.). Auth key per persona from `.env`. |
| `src/custom_exercise_templates.md` | Registry of custom Hevy exercise templates (not in standard library) — IDs, muscle groups, demo links. Check here before calling `create-exercise-template`. |
| `src/report.py` | Generates data snapshot (called by coach.py) — Garmin data only; Hevy data fetched live via hevy_service.py |
